# Задача: веб-приложение «Foodly!»

Создай в текущей папке одностраничное веб-приложение **Foodly!**: рецепты с расчётом КБЖУ, список покупок, помощник по плану питания на неделю, экспорт списка в PDF и тёмная/светлая тема. Интерфейс полностью на русском языке. Исходный бриф лежит в этой же папке (`deepseek_markdown_*.md`). Этот промпт его уточняет и дополняет, а при расхождениях **приоритет у этого промпта**.

## Порядок работы

1. Прочитай бриф и этот промпт. Затем коротко изложи план: модель данных, структуру `app.js` по секциям, алгоритм плана питания, подход к кириллице в PDF. Если что-то неясно, задай вопросы **до** начала кода.
2. Пиши поэтапно: данные и хранилище → рецепты → список покупок → план питания → PDF → PWA → полировка UI.
3. После каждого этапа проверяй работу в браузере через локальный сервер (`python3 -m http.server`) и смотри консоль на ошибки.
4. В конце пройди чек-лист приёмки (внизу) и отчитайся по каждому пункту.

## Технические рамки

- **Файлы:** `index.html`, `style.css`, `app.js`. Для PWA дополнительно `manifest.webmanifest`, `sw.js` и `icons/` (192 и 512 px, плюс maskable), для документации `README.md`. Сборщиков, фреймворков и npm нет.
- Приложение **должно полностью работать при открытии `index.html` двойным кликом** (`file://`). Поэтому `app.js` подключается обычным `<script>`, без ES-модулей (`type="module"` на `file://` не работает). Сервис-воркер регистрируется, только если `location.protocol` равен `http:` или `https:`. На `file://` приложение молча работает без него.
- Библиотеки только через CDN (jsDelivr или cdnjs) с зафиксированными версиями: `jsPDF`, опционально `SortableJS`.
- Хранение данных в `localStorage` под одним ключом-неймспейсом (например, `foodly:v1:*`). Нужны поле `schemaVersion` и функция миграций. Все чтения и записи оборачивай в try/catch. При переполнении квоты показывай понятное сообщение, приложение не должно падать.
- `app.js` структурирован по секциям с комментариями-заголовками: Storage, Models, Nutrition, Recipes, Shopping, Planner, PDF, Backup, UI/Router, Theme. Используй классы или IIFE-модули. Глобальных переменных нет, кроме одного неймспейса `Foodly`.
- Навигация по вкладкам через hash-роутинг: `#recipes`, `#shopping`, `#plan`, `#settings`. На телефоне нижний таб-бар, на десктопе верхняя навигация.

## Модель данных (ориентир, можно улучшить)

- **Product** (справочник продуктов): `id, name, category, per100: {kcal, protein, fat, carbs, fiber}, units: {шт?: граммы, "ст. л."?: граммы, "ч. л."?: граммы, мл?: плотность г/мл}, isCustom`
- **Recipe:** `id, title, photo?, servings, tags[], ingredients: [{productId, amount, unit}], steps[], createdAt, updatedAt`
- **ShoppingItem:** `id, name, productId?, amount, unit, category, checked, source: "manual" | "recipe" | "plan", sourceRefs[]`
- **Plan:** `id, createdAt, seed, settings, days: [{date, meals: [{slot, recipeId, portions}]}]`
- **Settings:** `theme, profile, targets, restrictions, mealsPerDay, people, categories[]`

## 1. Справочник продуктов и расчёт КБЖУ

- Встроенный справочник примерно на **150 распространённых продуктов**: овощи, фрукты, крупы, мясо, рыба, молочное, яйца, бакалея, масла, специи. Значения КБЖУ на 100 г должны быть реалистичными (по таблицам Скурихина или USDA). У каждого продукта есть категория (её используют группы списка покупок) и **вес единиц**: «1 шт яйцо = 55 г», «1 ст. л. масла = 17 г», плотность для мл (молоко ≈ 1,03 г/мл).
- В форме рецепта название ингредиента вводится с **автоподстановкой** из справочника. Если продукта нет, в той же форме открывается мини-форма нового продукта: КБЖУ на 100 г, категория, вес единицы. Новый продукт сохраняется в справочник (`isCustom: true`).
- Единицы: `г, кг, мл, л, шт, ст. л., ч. л., щепотка, по вкусу`. Для расчёта всё переводится в граммы. Позиции «по вкусу» и «щепотка» в КБЖУ не учитываются. Если у продукта не задан вес выбранной единицы, покажи предупреждение у ингредиента и попроси его указать.
- КБЖУ рецепта = сумма по ингредиентам, делённая на число порций. Показывай ккал, Б, Ж, У и клетчатку на порцию.
- В настройках есть раздел «Справочник продуктов»: просмотр, поиск, редактирование и удаление пользовательских продуктов. Встроенные продукты можно редактировать, но не удалять.

## 2. Рецепты

- CRUD рецептов. Поля: название, фото, число порций, ингредиенты, шаги (с drag&drop-сортировкой), теги.
- **Фото:** загрузка файла, который перед сохранением ужимается через canvas до ~800 px по длинной стороне (JPEG, качество ~0,75, в base64), либо URL. Без фото показывается аккуратная заглушка: градиент и эмодзи по типу блюда.
- **Теги:** тип приёма пищи (завтрак / обед / ужин / перекус, можно несколько), кухня, свободные теги. Автоматически вычисляемые бейджи: «Высокобелковое» (белок ≥ 25% калорий порции) и «Много клетчатки» (≥ 6 г на порцию).
- Поиск по названию и ингредиентам. Фильтры по тегам, типу приёма пищи и диапазону калорий на порцию. Сортировка: по названию, по калорийности, по новизне.
- Карточка рецепта: фото, название, бейдж ккал на порцию, мини-полоска Б/Ж/У. Полный просмотр рецепта открывается в модалке.
- Кнопка «В список покупок» с **выбором числа порций** (множитель). Ингредиенты масштабируются пропорционально.

## 3. Список покупок

- Три источника позиций: ручной ввод (с автоподстановкой из справочника, категория подставляется сама), рецепты (с множителем порций) и план питания.
- **Агрегация:** одинаковые продукты суммируются по `productId`, а при его отсутствии по нормализованному названию. Единицы приводятся к базовой (г/мл/шт) и отображаются удобно: 1500 г → 1,5 кг. Позиции «по вкусу» не суммируются, выводятся один раз. У агрегированной позиции видно, из каких рецептов она собрана.
- Группировка по категориям. Список категорий редактируется в настройках (добавить, переименовать, удалить, изменить порядок). Порядок категорий повторяет маршрут по магазину.
- Отметка «куплено»: купленное зачёркивается и уходит вниз группы. Кнопка «Очистить купленное». Количество правится вручную инлайн. Позицию можно удалить.
- Кнопки «Экспорт в PDF» и «Очистить список» (с подтверждением через собственную модалку, **без** `alert/confirm`).

## 4. Помощник по плану питания

**Профиль и цели:**
- Калькулятор: пол, возраст, рост, вес, уровень активности (5 уровней, коэффициенты 1,2–1,9), цель (похудение / поддержание / набор).
- Калории по формуле Миффлина–Сан Жеора × коэффициент активности. Для похудения −15%, для набора +10%.
- БЖУ по умолчанию: белок 1,6 г/кг (при похудении 2,0 г/кг), жиры 25–30% ккал, углеводы — остаток.
- Все рассчитанные значения можно **поправить вручную**. Кнопка «Пересчитать» возвращает расчётные.

**Ограничения:** исключаемые продукты (аллергии и нелюбимое) выбираются через автоподстановку из справочника. Рецепты, где они встречаются, в план не попадают. Отдельных диет-режимов не нужно. Есть переключатели предпочтений «больше белка» и «больше клетчатки»: они повышают приоритет рецептов с соответствующими бейджами.

**Параметры плана:** число приёмов пищи в день (3–5) и **число человек** (множитель для списка покупок; КБЖУ плана считается на одного).

**Алгоритм** (детерминированный, без внешних API):
- Используется seeded PRNG (например, mulberry32). Seed хранится в плане, поэтому одинаковые входные данные дают одинаковый план.
- Доли суточных калорий по приёмам пищи. 3 приёма: 30/40/30. 4 приёма: 25/35/10/30. 5 приёмов: 20/10/35/10/25. Перекус — слот «перекус».
- Для каждого слота берутся кандидаты с подходящим тегом, из них исключаются рецепты с запрещёнными продуктами. **Порции масштабируются с шагом 0,5 (от 0,5 до 2,5)**, чтобы попасть в калорийность слота.
- Жадный подбор со скорингом: отклонение от ккал и БЖУ слота плюс штрафы за повторы (одно блюдо не чаще 2 раз в неделю и не дважды в один день). Затем день донастраивается: порции корректируются, пока суммарное отклонение за день не станет **≤ ±10% по ккал** (по БЖУ насколько возможно).
- Если попасть в ±10% невозможно (мало рецептов после фильтров), план всё равно строится. У дня появляется предупреждение с причиной и подсказкой («добавьте рецепты-ужины» или «ослабьте ограничения»).

**UI плана:** 7 дней с датами начиная с выбранной даты. У каждого приёма пищи видны блюдо, порции и ккал. У каждого дня итоги КБЖУ и индикатор отклонения от цели (зелёный ≤10%, жёлтый ≤20%, красный >20%).

**Кнопки:** «Сгенерировать план», «Перегенерировать день» (новый seed только для этого дня), «Заменить блюдо» (модалка с отсортированными подходящими кандидатами и их влиянием на итог дня), ручная правка порций, «Сохранить план», «Собрать список покупок на неделю» (с учётом числа человек, с опцией заменить или дополнить текущий список).

## 5. Экспорт в PDF (jsPDF)

- **Кириллица:** стандартные шрифты jsPDF её не поддерживают. Нужно встроить TTF-шрифт с кириллицей (например, Roboto или PT Sans, обычный и полужирный) через `addFileToVFS` / `addFont`. Шрифт загружается с CDN при первом экспорте и кешируется (в памяти, а при наличии сервис-воркера в его кеше). Если шрифт не загрузился, покажи понятную ошибку, а не PDF с «кракозябрами».
- Вёрстка **mobile-first**: формат A5 книжный, одна колонка, поля 12 мм. Заголовок «Foodly! — Список покупок» с датой (20–22 pt). Заголовки категорий 16–18 pt, позиции ≥ 14 pt. Перед каждой позицией пустой квадратик-чекбокс для отметки карандашом. Количество выравнивается по правому краю. Длинные названия переносятся. Категория не рвётся между страницами, если помещается целиком. Внизу номера страниц.
- Опция «только некупленное» включена по умолчанию.
- Имя файла `shopping-list-YYYY-MM-DD.pdf`.

## 6. Резервная копия и данные

- В настройках есть «Экспорт данных» (скачивание JSON со всеми данными и `schemaVersion`) и «Импорт данных» с выбором: заменить всё или объединить. Перед импортом файл валидируется, при ошибке выводится понятное сообщение.
- Есть «Сбросить к демо-данным» (с подтверждением).

## 7. PWA и офлайн

- `manifest.webmanifest`: имя «Foodly!», тема и фон под палитру, иконки, `display: standalone`, `start_url: "./"`.
- `sw.js`: precache файлов приложения. CDN-библиотеки и шрифт PDF кешируются runtime-стратегией stale-while-revalidate. Кеш версионируется, старые версии удаляются при `activate`.
- Когда доступна новая версия, появляется ненавязчивый тост «Доступно обновление — обновить».
- Без сервиса-воркера (`file://`) всё, кроме офлайна и установки, работает так же.

## 8. Дизайн и UX

- Минимализм, много воздуха, скругления 12–16 px, мягкие тени. Шрифт Inter (Google Fonts) с фолбэком на `system-ui`.
- Все цвета — CSS-переменные в `:root`.
  - **Светлая тема:** фон близкий к белому, акценты мятный `#3ecf8e` и лавандовый `#a78bfa`.
  - **Тёмная тема:** графит `#1a1a1d` (фон) и `#232327` (поверхности), те же акценты. Проверь контраст текста на акцентных кнопках (WCAG AA).
- Переключатель темы в шапке. Выбор сохраняется в `localStorage`. При первом запуске учитывается `prefers-color-scheme`. Тема применяется до первой отрисовки, без вспышки.
- Микроанимации: hover карточек, появление модалок, плавная смена темы. Всё отключается при `prefers-reduced-motion`.
- Адаптив: телефон (от 360 px), планшет, десктоп. На телефоне нет горизонтальной прокрутки, тач-зоны ≥ 44 px.
- **Empty states** с подсказкой и кнопкой действия на каждом экране: нет рецептов, пустой список, нет плана, ничего не найдено.
- **Валидация форм** с сообщениями у полей. Обязательные поля: название, порции ≥ 1, хотя бы один ингредиент, количество > 0.
- Тосты для действий и «Отменить» для удаления (5 секунд).
- **Доступность:** модалки с `role="dialog"`, `aria-modal`, `aria-labelledby`, ловушкой фокуса, закрытием по Esc и возвратом фокуса. Переключатели с `role="switch"` / `aria-checked`. Видимый `:focus-visible`. Полноценная работа с клавиатуры. У иконок-кнопок есть `aria-label`.

## 9. Seed-данные

- **24 рецепта** обычной домашней кухни, без диетической специфики: примерно 6 завтраков, 6 обедов, 6 ужинов, 6 перекусов. Часть из них естественным образом получит бейджи «Высокобелковое» или «Много клетчатки».
- Ингредиенты ссылаются на продукты справочника, количества реалистичные, шаги понятные. Фото нет, используются заглушки.
- Проверь, что при целях 1600, 2000 и 2600 ккал без ограничений генератор строит неделю, в которой каждый день укладывается в ±10%.
